# Ideation: euro-azi (open focus) — 2026-10-14

## Subject

The whole repo, with no particular focus. euro-azi is a single-page app (`index.html`) served by GitHub Pages. It shows the official BNR reference rates and buy/sell quotes from 11 Romanian banks for EUR, USD, GBP and CHF, plus a BNR chart and an EUR/USD cross rate. `scraper.py` runs on weekdays from `.github/workflows/update.yml` (`cron: "0 6,10,13,16 * * 1-5"`, line 5) and commits `rates.json`.

Grounding (key points):

- **The BNR feed has been failing on every run, and the run still goes green.** In run 38457183921 (2026-10-13) the log shows `BNR esuat: syntax error: line 1, column 0`, `istoric 2025: raspuns neasteptat (posibil blocare), ignor`, `istoric 2026: …`, `Istoric BNR esuat: …`, then `OK: 2026-07-30 | banci: 11` and a commit.
- **`rates.json` has said `"data": "2026-07-30"` and `"bnr": {"EUR": 5.2439, …}` in all 50 commits that touch it** (2026-09-09 to 2026-10-13). The scraper falls back to the previous value without saying so (`scraper.py:153`, `scraper.py:157`).
- **The page shows that stale date as today's date.** The header is `dro(r.data)` (`index.html:111`), so visitors see "joi, 30 iulie 2026". Every bank's "vs BNR" difference is computed against the July rate.
- **The BNR history stops at 2025-12-31** (106 points per currency). The chart window is anchored to the last point (`index.html:110`), so "ultimele 30 zile" actually shows December 2025.
- **Stale bank quotes are carried forward forever, with no age** (`scraper.py:173-176`). ING Bank EUR has been `5.1284 / 5.3378` in every commit since 2026-09-09 while every other bank moved. It is also about 0.12 lei below the other banks.
- **Bank quotes are matched to a bank by taking the nearest bank name in the 300 characters before each buy/sell block** (`scraper.py:117-119`). There are no tests or fixtures.
- **No glossary, ADRs, README or issues exist.** All commits except one are bot rate updates.

Method note: no subagents were used. Grounding, generation and verification were all done sequentially by one agent in one context, so **no independent verifier checked this list**. Every `direct:` quote below was re-read against the file or the job log before it was written.

## Ranked ideas

### 1. Restore a working BNR reference rate

The official BNR feeds (`nbrfxrates.xml` and the yearly files) return something that is not XML when fetched from GitHub's runners. That looks like blocking. Pick a source that actually reaches the runner and keep the official feed as the first try. Candidate sources to evaluate: the BNR rate that cursvalutarbanci.ro already shows on the pages the scraper fetches, a different BNR endpoint, or a small relay/worker. Validate the parsed value against the same `PLAUS` ranges the bank parser uses.

- **Basis:** `direct:` job log 115502820089: `BNR esuat: syntax error: line 1, column 0` and `istoric 2026: raspuns neasteptat (posibil blocare), ignor`. `rates.json` has `"data": "2026-07-30"` in every commit from 2026-09-09 onward.
- **Why it matters:** BNR is the app's reference point. Every "vs BNR" figure and the chart are wrong until this is fixed.
- **Size:** M

```text
/supermatt:grill-with-docs Restore a working BNR reference rate in euro-azi. The GitHub Actions job logs `BNR esuat: syntax error: line 1, column 0` and `istoric 2025/2026: raspuns neasteptat (posibil blocare)` on every run (job 115502820089), and rates.json has been frozen at "data": "2026-07-30" for over two months because scraper.py:153/157 silently reuses the previous value. Decide which source the runner can actually reach (official feed first, then a fallback), how to validate the value, and what happens when every source fails. It matters because every bank's "vs BNR" difference and the chart depend on it.
```

### 2. Make stale data loud: fail the job and label the page

Have the scraper exit non-zero, or open or update a GitHub issue, when the BNR date falls more than N business days behind today or any source fails. Have the page stop presenting `r.data` as today's date and show its age instead, e.g. "BNR: 30 iulie (acum 76 zile)".

- **Basis:** `direct:` `scraper.py:182` prints `OK:` even after `BNR esuat`, and the job concludes `success`. `index.html:111` renders `dro(r.data)` as the page's date line.
- **Why it matters:** this broke for over two months without anyone noticing. Making failures visible is the cheapest way to make sure the next breakage gets caught.
- **Size:** S

```text
/supermatt:grill-with-docs Make stale data loud in euro-azi. Today the scraper prints "OK" (scraper.py:182) and the Actions job goes green even when the BNR fetch fails, and index.html:111 shows the stale BNR date (30 July 2026) as if it were today. Decide the staleness threshold, how the job signals it (fail, warning annotation, or an auto-opened issue), and how the page shows data age to visitors. It matters because the BNR feed has been broken since at least 9 Sep 2026 and nobody noticed.
```

### 3. Timestamp every bank quote and drop the stale ones

Store `seen` (the date a quote was last actually scraped) next to each bank quote. Show the age on the bank's row and hide or grey out quotes older than a threshold, instead of carrying them forward forever.

- **Basis:** `direct:` `scraper.py:173-176` copies any previous quote that wasn't found in this run, with no date. ING Bank EUR is `5.1284 / 5.3378` in every commit from 2026-09-09 to 2026-10-13 while other banks changed every run, and it sits about 0.12 lei below its peers.
- **Why it matters:** the page ranks banks as "cel mai ieftin" or "cel mai mult". A frozen quote can win the ranking with a price the bank no longer offers.
- **Size:** S

```text
/supermatt:grill-with-docs Add per-quote freshness to euro-azi's bank rates. scraper.py:173-176 carries any missing bank quote forward with no timestamp; ING Bank EUR has been 5.1284/5.3378 in every rates.json commit since 2026-09-09 while all other banks moved, and it sits ~0.12 lei below its peers. Decide what "stale" means, how to store the last-seen date, and how the ranking in index.html treats stale quotes. It matters because a frozen quote can be ranked "cel mai ieftin" even though the bank no longer offers that price.
```

### 4. Grow the history inside rates.json instead of re-downloading it

Append each day's BNR rate to `history` (deduplicated by date, trimmed to about 400 days) instead of rebuilding it from the yearly BNR files on every run. A missing yearly file then stops wiping out recent data, and the chart window starts from today rather than from the last available point.

- **Basis:** `direct:` `scraper.py:64-99` rebuilds the history each run, and `return hist if got else None` (line 99) accepts whatever it got, which is 2025 only. The history ends `2025-12-31`. `index.html:110` anchors the range to `hist[hist.length-1].date`.
- **Why it matters:** the chart labelled "ultimele 30 zile" currently shows December 2025. Owning the history means one bad source day no longer erases a year.
- **Size:** S (assuming #1 provides a daily value)

```text
/supermatt:grill-with-docs Make euro-azi accumulate BNR history itself. scraper.py:64-99 rebuilds history from yearly BNR files every run and accepts partial results (line 99), so rates.json history now ends 2025-12-31 and index.html:110 anchors "ultimele 30 zile" to that last point, showing December 2025. Decide how to append, dedupe and trim, how to backfill the gap, and how the chart window should be anchored. It matters because the chart is currently ten months out of date.
```

### 5. Fixture tests for the scrapers

Save one real HTML page per currency and one BNR XML file as fixtures. Add a small test that checks each of the 11 banks parses to plausible buy < sell values, plus a test for the BNR parser. Run the tests in the workflow before committing.

- **Basis:** `direct:` `scraper.py:117-119` attributes each quote to the nearest bank name in the 300 characters before it. The repo contains no tests. `reasoned:` a layout change on the source site can silently attach a quote to the wrong bank, and #3's ING anomaly is exactly that kind of symptom.
- **Why it matters:** it turns the next silent breakage into a failing check, and it makes changing #1 and #3 safe.
- **Size:** S

```text
/supermatt:grill-with-docs Add fixture tests to euro-azi's scraper. Bank quotes are attributed by searching for the nearest bank name in the 300 chars before each buy/sell block (scraper.py:117-119) and there are no tests; ING's EUR quote has been frozen and ~0.12 lei off its peers since 2026-09-09. Decide which fixtures to capture, what to assert (every bank found, plausible range, buy < sell), and whether the workflow should refuse to commit when tests fail. It matters because parser breakage is currently invisible.
```

### 6. An amount converter on the main card

Add an amount field ("Am 500 €" or "Vreau 2 000 €") that shows the lei total at the best bank and how much that saves compared with the worst bank and with BNR.

- **Basis:** `reasoned:` the page already ranks banks by price (`index.html:118-119`) and shows the difference per unit, but the decision a visitor actually makes is about a sum. The saving in lei is the number that makes the ranking useful. `direct:` the spread and the "vs BNR" figures are already computed per row (`index.html:133-137`).
- **Why it matters:** it turns a rate table into an answer: "go to X, you save Y lei".
- **Size:** S

```text
/supermatt:grill-with-docs Add an amount converter to euro-azi. index.html already ranks banks per unit (lines 118-119) and computes "vs BNR" and the spread per row (133-137), but visitors decide on a sum. Decide the input UX, whether to persist the amount, and which comparisons to show (best vs worst bank, vs BNR). It matters because a lei saving is the number people act on.
```

## Cut

| Idea | Reason |
|---|---|
| Combination: BNR fix + staleness gate + own history in one change | Duplicate of stronger ideas: ranked separately as #1, #2 and #4 so each can ship on its own |
| Price alerts (notify when the best EUR sell price drops below a threshold) | Cost over value until #1–#3 make the data trustworthy. Alerts on stale quotes would mislead |
| PWA manifest and offline service worker | Cost over value: `index.html:10-12` already gives a home-screen app, and offline mode would only serve old data |
| Card-network and fintech rates (Visa/Mastercard/Revolut) next to bank rates | Cost over value: more fragile scraping sources while the existing ones are already failing silently |
| Per-bank "who is cheapest most often" leaderboard | Vague, and depends on bank history that #3/#4 would have to establish first |
| Stop committing `rates.json` every run; deploy through a Pages artifact | Cost over value: the commit churn is harmless, and git history was what made this diagnosis possible |
| Cron runs fewer times than scheduled | No basis: only runs that changed something leave a commit, so the commits can't show this |
| Pin "my bank" at the top | Vague: with 11 rows the gain is marginal |
